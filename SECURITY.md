# Security policy

Report vulnerabilities privately to the affected project's maintainers through an established private project communication channel. For repositories with private vulnerability reporting enabled, use that reporting feature.

Include the affected version or revision, a description of the issue, and reproducible steps using synthetic data. Do not include passwords, tokens, signing keys, customer records, or private account data.

Do not publish sensitive vulnerability details in public issues, pull requests, or discussions. Coordinate disclosure and remediation with the project maintainers.
